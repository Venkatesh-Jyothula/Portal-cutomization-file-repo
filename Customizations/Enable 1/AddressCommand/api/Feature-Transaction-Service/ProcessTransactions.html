ProcessTransactions

Synchronously processes CUD transactions on feature data. The transactions are processed in a job specified in parameters or outside of a job context (STT mode), if not job was specified. The result of the transaction is returned in output. It includes newly created identifiers (e.g. G3E_FID, G3E_CID, G3E_DETAILID), mapped to temporary identifiers in the request.

See also:

  • Internal workflow for details on processing.
  • Hyperlink mapping

Request

Method

POST

URL Template

/transaction[?jobs={jobs}&lcid={lcid}]

Query params

Name Type Mandatory Description
jobs String Job identifier. When not present, the transaction is executed without a job context.
lcid String LCID to use when retrieving metadata. When not present, the default LCID is used – explicitly configured LCID in service settings or the current culture of the process if no LCID is configured.

Request body

Instance of ProcessTransactionRequest.

ProcessTransactionRequest

Name Type Mandatory Description
transactions Array of Transaction Y List of transactions to process.

Transaction

Name Type Mandatory Description
type String Y Type of the transaction
tref Int Transaction reference. The value is copied to the corresponding element in the output, to be used by the caller to correlate transaction entries in request and response. Not used internally by the transaction processing.

Allowed transaction types:

Name Description
CreateFeature Create a new feature.
UpdateFeature Update an existing feature.
DeleteFeature Delete an existing feature completely.
CreateComponent Create a component instance in a newly created or existing feature instance.
UpdateComponent Update a component instance in an existing feature instance.
DeleteComponent Delete a component instance in an existing feature instance.
EstablishRelationship Establish a relationship between two features. Any of the features can be new or already exist in the database.
DeleteRelatioship Delete relationship between two features. The relationship must already exist.
CreateDetail Create a new detail window (G3E_DETAILID).
UpdateDetail Update an existing detail window (identified by G3E_DETAILID).
AttachDetail Attach a detail window to detail attribute component of a feature.
DetachDetail Detach a detail window from detail attribute component of a feature.

A CreateFeature or UpdateFeature record is needed when updating feature attributes, creating or deleting components or establishing/deleting relationships (for features on both sides of the relationship).

ComponentTransactionBase

Derived from Transaction. The type attribute must match one of the following:

CreateComponent creates a new component instance in related feature and sets its attributes. For non-repeating components of a feature, it behaves like Create-or-Update (if G3E_CID is not specified). If G3E_CID is specified, it must not match any existing row. For repeating components, a new row is always created.

UpdateComponent updates attributes of a component instance. For non-repeating components of a feature, it behaves like Create-or-Update (if G3E_CID is not specified). If G3E_CID is specified, it must match an existing row. For repeating components, G3E_CID is mandatory.

DeleteComponent deletes a component instance. G3E_CID is mandatory.

Name Type Mandatory Description
fref Int Y Feature reference. References fref in a CreateFeature or UpdateFeature record which preceeds this transaction.
G3E_CNO Int Y G3E_CNO
G3E_CID Int (Y) G3E_CID. For CreateComponent the value is optional, for UpdateComponent it is mandatory only for repeating components, for DeleteComponent it is mandatory.
dref Int Detail (schematic) window reference. Identifies a CreateDetail or UpdateDetail transaction which precedes this transaction.

When populated, G3E_DETAILID from the detail transaction is written into this component instance.
attributes object Attribute values encoded as JSON object.

The property key is the attribute field name in uppercase. LTT key attributes (G3E_ID, G3E_FNO, G3E_FID, G3E_CNO, G3D_CID) are ignored even if present.

The property value is the attribute value.

See Attribute value encoding.

DetailTransactionBase

Derived from Transaction. The type attribute must match one of the following:

CreateDetail transaction creates a new detail window reference. Technically this only means that a new G3E_DETAILID is generated. Subsequent AttachDetail command must be received to attach this G3E_DETAILID to a detail attribute component of a feature. CreateDetail allows explicit G3E_DETAILID to be passed in. Newly created G3E_DETAILID is reported in response.

UpdateDetail does the same as CreateDetail, except for that it requires G3E_DETAILID to be passed in. Alternatively, it can be retrieved from other CreateDetail or UpdateDetail within the same transaction if multiple detail references to the same G3E_DETAILID need to be created (with different attributes).

Name Type Mandatory Description
dref Int Y Detail (schematic) window reference. The value identifies this detail window in other transactions in the request. This mechanism enables referencing detail windows before their G3E_DETAILID is available.
G3E_DETAILID Int G3E_DETAILID – identifier of the detail window. When processing a CreateDetail window, this value is optional. If missing, a new value is generated from the database.
relateddref Int Detail transaction reference. When this property is populated, it must contain a valid dref in this transaction, which resolves to a valid G3E_DETAILID.

The design goal of this property is to allow the caller to create multiple references to the same detail window (identified by G3E_DETAILID) with possibly different attributes.
attributes object Detail window attribute values encoded as JSON object. The encoding is the same is in CreateComponent. See Detail window attributes (below) for a list of allowed attribute names.

DetailReferenceTransactionBase

Derived from Transaction. The type attribute must match one of the following:

  • AttachDetail
  • DetachDetail

AttachDetail transaction attaches a detail window to a detail attribute component of a feature. If there is more than one component which can store detail attribute reference, a related component transaction (CreateComponent or UpdateComponent) must be referenced to properly identify the G3E_CNO, and for repeating components, also G3E_CID. If the component is not repeating, the transaction creates instance of the detail attribute component and updates its attributes. If the component is repeating and does not exist yet, a new component instance is created. If it necessary to create or update a specific instance, issue a CreateComponent or UpdateComponent transaction before AttachDetail and reference it using componenttref.

DetachDetail detaches the G3E_DETAILID from the detail attribute component of the instance. The transaction looks for G3E_DETAILID in detail attribute records and sets the attribute to NULL if it matches. If componenttref is populated, G3E_DETAILID is only removed when both G3E_CNO, G3E_CID and G3E_DETAILID match. This way it’s possible to selectively remove a detail from a feature.

Name Type Mandatory Description
fref Int Y Feature reference. References fref in a CreateFeature or UpdateFeature record which preceeds this transaction.
dref Int Y Detail (schematic) window reference. Identifies a CreateDetail or UpdateDetail transaction which precedes this transaction.
componenttref Int Component transaction reference. When this property is populated, it must contain a valid tref in this transaction, which identifies a CreateComponent or UpdateComponent transaction which precedes this transaction.

AttachDetail or UpdateDetail uses G3E_CNO and G3E_CID values to precisely identify the component instance to update.

Response

The response contains a list of transactions in the same structure as the request, except:

  • property tref is the same as in the request object. This enables matching transaction records in request and response.
  • attributes are not written to the response.
  • newly generated G3E_CID and/or G3E_CID values are present.
  • errors property contains a list of errors from validation or processing. If any error is present (with some exceptions, see table), the transactions in the request were not executed and the HTTP status code is 400.
  • links property contains mapped hyperlink and file references. source property contains the original value passed in the request, destination contains the mapped physical path. The file is not copied by Feature Transaction Service, it is the duty of the caller to use source and destination to do the physical file operation.
