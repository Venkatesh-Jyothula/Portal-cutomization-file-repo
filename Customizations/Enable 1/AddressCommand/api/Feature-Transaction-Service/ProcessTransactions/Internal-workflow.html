Internal workflow

Feature CRUD

Feature CUD transactions are executed in the order specified in the request. It is therefore important that transactions which establish context (CreateFeature, UpdateFeature, CreateDetail, UpdateDetail) precede those which reference given feature or detail window.

Transaction Processing
CreateFeature * Generate G3E_FID from database.
* Initialize internal mapping (fref -> G3E_FID).
UpdateFeature * Initialize internal mapping (fref -> G3E_FID).
DeleteFeature * Initialize internal mapping (fref -> G3E_FID).
* Mark given (G3E_FNO, G3E_FID) pair for deletion.
CreateDetail * Generate G3E_DETAILID from database (if not explicitly specified in request).
* Initialize internal mapping (dref -> G3E_DETAILID).
UpdateDetail * Initialize internal mapping (dref -> G3E_DETAILID).
CreateComponent * When editing, load existing component instances from database.
* Add new component instance.
* Determine new G3E_CID (as maximum + 1)
* Set attribute values from request.
* Set G3E_DETAILID (if requested)
UpdateComponent * Load existing component instances from database.
* Find component instance by G3E_CID.
* Set attribute values from request.
* Set G3E_DETAILID (if requested)
DeleteComponent * Load existing component instances from database.
* Find component instance by G3E_CID.
* Mark component for deletion.
AttachDetail * Determine detail attribute component from metadata.
* Create new detail attribute component instance (if it does not exist) or find existing component instance (using componenttref)
* Compute detail MBR from data in request.
* Perform configuration to storage coordinate transformation.
* Set detail reference attributes (from referenced CreateDetail or UpdateDetail).
DetachDetail * Determine detail attribute component from metadata.
* Create new detail attribute component instance (if it does not exist) or find existing component instance (using componenttref)
* Remove G3E_DETAILID (set to NULL)

Functional interfaces

Feature Transaction Service is not binary-compatible with original G3E.exe model, therefore it does not support direct execution of Functional and other interfaces. Some built-in interfaces are reimplemented for the FTS model and executed:

  • PFIFace.SetSubsettingAttribute Computes regional subsetting region from feature geometry and sets the subsetting attribute.

Serialize model to database transactions

The cumulative updates done to the feature object model in memory are executed as individual DELETE, UPDATE or INSERT statements to the database. Multiple updates to the same component by more than one transaction result in only one command.

The logic in pseudo-code:

For each feature in current transaction:
    If (feature is marked for deletion)
        For each component (order by G3E_DELETEORDINAL)
           Delete all instances 
    Else
        For each component (order by G3E_DELETEORDINAL) 
            If "deleted"
                DELETE
        For each component (order by G3E_INSERTORDINAL)
            If "updated"
                UPDATE (updated attributes)
            If "inserted"
                INSERT (attributes with explicitly set values)

Relationships

Relationship processing in FTS matches logic implemented by Relationship Manager in HxGN NetWorks Core.

EstablishRelationship transaction processing:

Ownership

  • Create support component in parent (if needed).
  • Get G3E_ID of parent component (this involves a database request).
  • Create support component in child (if needed).
  • Set owner ID field in child.

Many-Ownership

  • Create support component in parent (if needed).
  • Verify that parent is not already among existing parents in child support component.
  • Create support component in child (if needed).
  • Set owner in child component.

Node-Edge Connectivity

  • Create support component in active feature (if needed).
  • Create support component in related feature (if needed).
  • Find node IDs for both features.
  • Determine new node ID
    • If both are NULL or 0, generate new ID from sequence in database.
    • If node ID of active feature is empty, use ID of related feature.
    • If both IDs are populated, use node ID of related feature.
  • Set corresponding node attributes.

Node-Ordered Connectivity

  • Determine Linear feature from Active and Related feature.
  • Create support component in Linear feature (if needed).
  • Update corresponding FNO and FID fields.

DeleteRelationship transaction processing:

Ownership

  • Get support component in parent (if needed).
  • Get G3E_ID of parent component.
  • Get support component in child (if needed).
  • Check if relationship exists.
  • Set child owner ID to NULL.

Many-Ownership

  • Get support component in child (if needed).
  • Find related component instance with related parent feature.
  • Delete component instance in child.

Node-Edge Connectivity

  • Get list of related features of active feature.
  • Get list of related features of related feature.
  • Get support component in active feature.
  • Get support component in related feature.
  • Set corresponding nodes (see table below).

Node-Ordered Connectivity

  • Determine Linear feature from Active and Related feature.
  • Get support component in Linear feature (if needed).
  • Find related (non-Linear) feature row.
  • Update corresponding FNO and FID fields to NULL.
