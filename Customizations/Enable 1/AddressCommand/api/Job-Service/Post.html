Post

Post pending edits for the specified job.

POST

Request URL Template

http://{HostName}/{JobServiceName}/job/{jobId}/post?pageNo={pageNo}&pageSize={pageSize}

Request Parameters

A list of validation errors is returned for the specified job. Job has to have pending edits. PageNo and pageSize are used for paging the result.

Parameter Name Description
jobId Job identifier
pageNo Number of the page for paged result.
pageSize Size of one page for paged result.

Sample Request

http://localhost/NetworksJobService/job/j303/post

Sample Response

The list of validation errors for job 'j303'.

[
    {
        "ErrorDescription": "desc",
        "ErrorLocation": "loc",
        "ErrorPriority": "P4",
        "FeatureKey": {
            "Fno": 202,
            "Cno": 13,
            "Fid": 322769,
            "Cid": 3
        }
    }
]

GET

Post all pending edits within the specified job. The edited features will be checked to make sure that all required components, attributes and relationships have been created. Also, the Validate method of all associated Functional interfaces and Validation interfaces will be executed.

If there are no validation errors at or above the metadata configured validation priority, then the job's feature edits will be checked for conflicts with master records of the same features that were posted by other jobs.

If there are no job conflicts, then the HxGN NetWorks Core Job Life Cycle processing occurs (if configured). If the Job Life Cycle processing succeeds, then the feature edits are posted in the database.

Request URL Template

http://{HostName}/{JobServiceName}/post/{jobId}

Request Parameters

Parameter Name Description
jobId The job identifier for the job. It must be an exact match to the job identifier in the job table.

Sample Request

http://localhost/NetworksJobService/post/WmsTestJob

Sample Response

A JSON array of validation error objects is returned. Only the validation errors that are blocking the post operation are returned. For example, if G3E_GeneralParameter_Optable's ValidationPriority value is "P2", then only the P1 and P2 error objects are returned. Each object specifies the feature keys, error priority, error description and error location as follows:

// JSON array of validation errors.
[
  { 
    "Fno":<featureNumber>,
    "Fid":<featureId>,
    "Cno":<componentNumber>,
    "Cid":<componentId>,
    "ErrorPriority":<either "P1","P2","P3", or "P4">,
    "ErrorDescription":<error message>,
    "ErrorLocation":<software component that reported error>
  },
  ...
]

Remarks All pending edits within the specified job are posted to the database. The job remains open.
