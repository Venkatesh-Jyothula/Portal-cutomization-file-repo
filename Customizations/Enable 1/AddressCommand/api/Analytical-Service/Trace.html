Trace API Overview

The HxGN NetWorks Analytical web service provides methods that allow clients to perform metadata defined traces of the HxGN NetWorks Core data's connectivity model.

Supported Trace Workflows

Dynamically discover the Analytical service

Call the NetWorksSolutionService/{alias}/analytical method to retrieve information on the deployed analytical service for this configuration.

Initialize the client to use the Analytical service trace functionality: Call the /Trace/SeedFnos method to retrieve the list of feature types that can start a trace. This information could be used by the client to enable trace workflows when the selected feature type is in the list of seed Fnos.

Perform a predefined trace

When the user selects a feature and the feature type (FNO) matches one of the trace seed Fnos, the client can call /Trace/Types/{fno} to get the list of predefined trace definitions for that feature type. Each trace definition includes a user visible name to display, the trace mappingId and the trace type (from G3E_TRACETYPES table).

When the user selects the desired trace definition, the client uses the corresponding trace MappingId value to call the /Trace/Parameters/{mappingId} method to retrieve the full description of the trace inputs that are needed to execute the trace. The response tells the client whether hint and / or goal features need to be determined and whether there are trace attribute values that need to be collected from the user for the trace filter or stop criteria.

If the trace parameter's PromptForHint property is true, then call the /Trace/Hint?SeedFID={seedFid}&MappingId={mappingId} method to get a list of candidate features that can serve as the hint feature for the trace. If the trace definition's PromptForGoal property is true, then the client directs the user to select a terminating feature for the trace. If the GoalFnoCandidates list is not null, then the terminating feature's type must match one of the Fnos in the GoalFnoCandidates list.

If the trace parameter's Attributes property is not empty, then the client must use the information to collect attribute values that will be used by the trace filter or stop criteria. If the Attributes IsPickListAttribute property is true, the client can call /Trace/Picklistvalues/{ano} to get the Json array of picklist key-value pairs to display to the user.

The user must supply a name for the trace results. The client can call /Trace/Exists/{traceName} to determine whether or not the specified trace result name already exists. If it does exist, the client can either get another name from the user, or ask the user if he wants to overwrite the previous trace results that are associated with the specified name. The trace result UserName and Overwrite properties are part of the execute method's POST body.

When all trace parameter values have been collected and formatted into the POST body Json format, call the /trace/execute method to run the trace in the database, store the trace results in database tables and get the trace number (TNO) for the result set as the response.

Spatially restrict trace execution

The set of features returned by a trace execution can be restricted to just those feature that are within a spatial area. The spatial area can be defined in the trace execute POST body as either an AOI parameter or a SpatialFilter parameter - but not both.

An array of AOI objects is returned from the {analyticalService}/Areas controller. The client could display the areas and let the user pick an area of interest to restrict his trace to. Alternatively, the client could allow the user to create a GeoJson polygon and send it as the "SpatialFilter" parameter in the POST body. In both cases, the metadata defined values for AOI threshold limits and the ability to override the limits will be applied.

Measure features in a trace result

Any trace execution result set can be augmented with the measurement of the features. If the MeasureFeatures parameter in the POST body is set to true, then the three additional columns, LENGTH, AREA, and PERCENT, are added to the results. For linear geometry features, the LENGTH column contains the measured length in the units of the current configuration. Likewise, area geometry features contain the measured area. If the search result was spatially restricted by either an Aoi or an adhoc spatial filter, then the PERCENT column contains the ratio of the measure of the part of the feature geometry that is inside the spatial boundary divided by the measure of the total geometry. By default, all measurements are done using the curved Earth reference space, but the client can override that by setting the MeasureOnCurvedEarth parameter to false, which will measure using the projection reference space.

Display the trace results on the map view

The response to any successful trace execution includes the trace number of the result set. This trace number (TNO) is the "handle" to the saved trace results in the database. The dynamic layer name for this trace result is Trace.{tno}. To display the results on the map view, the client first calls the WMS GetLayer method with LAYERS=Trace.{tno} to get the GetCapabilities response that includes the bounding box to fit the map to in a subsequent call to the WMS GetMap method that also specifies the LAYERS=Trace.{tno}. (See WMS Service methods for details).

Retrieve previously saved trace results

When a trace is executed, the trace results are saved in tables in the database until the client explicitly deletes them. Call the /Trace/Traces method to get a Json list of the trace number (TNO) and trace name of every saved trace result set. This list could be presented to the user so he can select a previously executed trace for redisplay or for custom processing.

Call the /Trace/Results/{tno} method to return a Json array of the trace results. The client could display the information as a data grid to allow the user to examine the features in the trace one at a time.

Augment the Trace Results

Any trace result set can be augmented with new attributes by providing the AUGMENT optional parameter. User can provide attribute numbers and attribute field name as input to the AUGMENT parameter. Call the /Trace/Results/{tno}?Augment={Attribute Number}&Augment={ComponentName.AttributeFieldName} to retrieve augmented parameters along with the trace result set.

Aggregation on Trace Results

Aggregation can be performed on the result set by providing aggregate optional parameters. Supported aggregates are SUM, MIN, MAX, AVG, GROUPBY, ORDERBY and DISTINCT. User can provide attribute numbers or response field names that needs to participate in the aggregate operation. Simple arithmetic operations can also be performed on the response fields for aggregation. Supported operators for arithmetic operation are +, -, *, /. The arithmetic expression will be evaluated for each response item and then the resulting aggregation will be performed. Call the /Trace/Results/{tno}?Sum={parameterName}&Min={parameterName}&Max={parameterName}&Avg={parameterName} to perform aggregation on the trace result set.

Substitute on Trace Results

Substitute operation can be performed on the result set parameters by providing the SUBST optional parameter. It is performed on individual attributes or attributes in specific ranges. All the operators supported by DataTable can be used in substitute operation. Call the /Trace/Results/{tno}?Subst={Substitute ParameterName},{Condition},{Substituted Value} to perform substitution functionality on the trace result set.

Function Call on Trace Results

An Oracle function which returns a scalar value can be executed by providing the FUNCTION optional parameter. The resultant value is added as a new parameter to the Trace result set. Call the /Trace/Results/{tno}?Function={OracleFunctionName}@{ParameterName} to execute the oracle function and add to the trace result set.

Delete trace results

Call the /trace/delete/{trace name} method to cleanup the saved trace results in the database. It is the client's responsibility to do this cleanup since it is the only one that knows when it is finished working with a specific trace result.

Methods

Method Uri Description
GET /Types Returns all trace definitions which are present in the connected database.
GET /Types/{FeatureNumber} Returns the list of trace definitions for the given feature number which are present in the connected database.
GET /Parameters/{TraceMappingID} Returns the trace parameters for the given trace mapping identifier.
GET /Delete/{TraceName} Deletes the trace if exists.
GET /Exists/{TraceName} Returns true if the given tracename exists.
GET /PickListValues/{ANO} Returns the picklist values for the given attribute number.
POST /Execute Executes the trace and returns a tracenumber for the given input parameters.
GET /hint?SeedFID={seedFID}&mappingID={mappingID} Returns the list of hint feature instances for the given seedFid and mappingID.
GET /SeedFNOs Returns all the FNO's that are eligible to perform trace.
GET /MappingId?TraceId={TraceID}&SeedFno={SeedFNO}&TraceType={TraceType}&TraceUsername={TraceUsername} Returns the MappingId for the given TraceId, SeedFno, and either TraceType or TraceUsername.
GET /Reports/{mappingId} Returns the list of valid report for given mappingID.
POST /ComputeMarkers/{tno}?rpno={rpno} Computes marker points for executed cost constraint trace.
POST /computemarkerpoints Computes the marker location points for an executed trace based on user defined stop criteria.
