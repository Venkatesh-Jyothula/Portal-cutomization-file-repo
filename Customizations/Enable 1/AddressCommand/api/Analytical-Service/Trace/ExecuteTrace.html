ExecuteTrace

Executes the trace and returns a tracenumber for the given input parameters.

POST

Request URL Template

http://{HostName}/{TraceServiceName}/Trace/execute?[Jobs={list of job names} | ActiveJob={job name}]

Request Parameters

Parameter Name Description
ActiveJob Optional job name whose pending edits will participate in the operation.
Jobs Optional comma separated list of jobs whose pending edits will participate in the operation.

Post Body Parameters

Parameter Name Description Required
SeedFno describes the seed feature type. Yes
SeedFid is the feature identifier from where the trace should be started and checks whether it belongs to the given SeedFno or not. Yes
UserName is the user defined name for trace. Yes
MappingId should be a unique identifier for the given SeedFno. Yes
HintIdentifiesFeature is a boolean value and is used in executing the trace in the selected hint feature direction. No
OverWrite a boolean value to overwrite the existing trace. No
Attributes required for executing trace. No
GoalFid the feature identifier where the trace should be stopped. No
HintFid used to choose the trace direction based on given feature identifier. No
Aoi Object returned by the Areas endpoint. Used to enable an AOI and/or AOILI restriction in trace execution. No
OverrideAoiThreshold The AoiMultiThreshold is a metadata defined limit for the maximum number of possible features from an AOI area to process in the trace. (See the G3E_GENERALPARAMETER topic in the HxGN NetWorks Core Admin help). If the AoiOverwriteThreshold metadata parameter is set to -1 (meaning override is possible); and if the current database user has the role associated with G3E_AOIOverwriteThreshold in the G3E_ROLEASSOC_OPTABLE, then this OverrideAoiThreshold POST body parameter controls whether or not the limit will be enforced. When OverrideAoiThreshold is set to false and the AOI contains more possible feature instances than the limit, the trace execution will return an error message that denotes how many possible features were in the trace. When this value is set to true, the trace execution continues and returns all results. The default value is false. No
SpatialFilter Specifies a GeoJson Polygon that is used to restrict the trace execution results. All of the features in the trace result will be restricted to features that are within or touching the specified polygon. Detail features are included if their geographic referencing feature is in the polygon. Polygon is the only geometry type supported for spatial filters. A trace request cannot contain both an AOI and a SpatialFilter value. The OverrideAoiThreshold parameter and the associated AOI processing also apply to the area defined by the spatial filter. No
MeasureFeatures When specified as true, the trace result will be augmented with the length or area measurement of each feature that can be measured. If the trace result was restricted by an AOI or spatial filter polygon, then the percentage of the features that fall within the spatial filter area will also be computed. Specifically, the geometry of the features that intersect the spatial boundary will be clipped and measured and the clipped measurement / the original measurement will be reported as a percent value. No
MeasureOnCurvedEarth When specified as true, the length or area measurement of each feature will be done using the geographic reference space; otherwise, the measurements will be done on the projection reference space. No
StartingPointX X coordinate for the Cost Constraint Trace starting point. No
StartingPointY Y coordinate for the Cost Constraint Trace starting point. No

Sample Response

If the trace request enabled an AOI or AOILI restriction and the number of features in the trace exceeded the AoiMultiThreshold in metadata, then the request fails. If the user has the necessary user role to override the threshold, then the following message is returned: "The number of trace result features in the area of interest, {0}, exceeds the threshold, {1}. Do you want to override the threshold and retrieve all results?" If the user wants to override, the client should resubmit the trace execute request with "OverrideAoiThreshold": true added to the POST body of the request.

If the user doesn't have the override role, or if the metadata prevents overrides, then the trace fails with the following message: "The number of trace result features in the area of interest, {0}, exceeds the threshold, {1}."

If the trace was successful, then the trace result number (tno) is returned. Clients use the /trace/results/{tno} method to retrieve the actual trace results.
