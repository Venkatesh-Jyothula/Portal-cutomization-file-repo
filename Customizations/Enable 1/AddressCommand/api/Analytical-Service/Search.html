Search

The HxGN NetWorks Analytical web service provides methods that allow clients to query the HxGN NetWorks Core data using the metadata defined finds and simple attribute queries. It also supports the retrieval of information about available details and schematics.

Supported Search Workflows

Dynamically discover the Analytical service:

Call the NetWorksSolutionService/{alias}/analytical method to retrieve information on the deployed analytical service for this configuration.

Initialize the client to use the Analytical service:

Call the /search/settings method to retrieve information on the deployed analytical service's limits on detail results, search results and the format of date values when sending dates as input parameters.

Call the /search/details/fnos and /search/schematics/fnos methods to retrieve the list of feature types that can have details or schematics. This information could be used to enable the client to search for details when a feature is selected (i.e. the selected feature's FNO is in the list).

Search for Details or Schematics so user can view it:

There are a number of different ways to retrieve information on details or schematics. All of them return the same response which contains information that can be displayed to the user to make a selection, and information needed to display the selected detail or schematic map view.

Call the /Search/Details or /Search/Schematics method to return a JSON response that provides details about the all available details or schematics. The client could display the information as a list or drop down and allow the user to select one.

Call the /Search/Details/fnos/{fno} or /Search/Schematics/fnos/{fno} method to return a JSON response that provides details about the all available details or schematics that match the specified feature type.

Call the /Search/Details/names?name={name} or /Search/Schematics/names?name={name} method to return a JSON response that provides details about the all available details or schematics that match the specified feature name. The {name} value will be automatically wildcarded on the end of the value to allow the user to just enter a few letters before the client executes a search. The search by name methods also allow the explicit wildcard character '%' to be added in the value. For example, name=FEM would match a detail named, FEMRITE, and name='%RIT' would also match FEMRITE.

Call the /Search/Details/fnos/{fno}/names?name={name} or /Search/Schematics/fnos/{fno}/names?name={name} method to return a JSON response that provides details about the all available details or schematics that match the specified feature type and name value.

Display the detail or schematic map view

Within the response to any search for details or schematics, the Details object contains the ID, NAME, and LSNO values for the detail or schematic. The NAME value is what should be displayed to the user. The LSNO value is used to dynamically discover the WMS service that can display the map image, and the ID is the detailID or schematicID that will be used in the dynamic layer name in the Layers parameter when calling the WMS for details.

Call the NetWorksSolutionService/{alias}/wms/{lsno} method to get the information on the WMS service that can display the detail or schematic in a map view. Then call the GetLayer method of that WMS for details service with LAYERS=Detail.{ID value} to get the GetCapabilities response that includes the bounding box to fit the map to in a subsequent call to the WMS GetMap method that also specifies the Layers=Detail.{ID value}. (See WMS Service methods for details).

Perform a predefined search for feature data

Call the /search/quicksearches method to get the list of quick searches to display, typically in a drop down combobox that allows the user to select from the list. The single input field could be either a text box or a drop down combobox depending on whether the parameter type is a picklist. If the parameter type in the quicksearch definition is anything other than a picklist, then the client would display a parameter label and a textbox field to collect the input value. If the parameter type is picklist, then the client would call the /search/picklistvalues/{ano} method to get the picklist key - value pairs to populate a combobox. The picklist value is the user visible value to show in the combobox, but the picklist key value is what should be passed to the execute method for the corresponding parameter.

Call the /search/searches method to get the list of all searches that are not quick searches. The client could display a flat list of these searches or it could group them by their search category. Call the /search/searches/categories method to get the category number and user visible name for all categories. Specifically, the client can group the search definitions under the search category whose G3E_ACNO values match. The parameter handling is the same as the quicksearch, except that there can be zero or more parameters. The parameters can be picklist, text, date-time, long or double values. If the search definition specifies that the parameter is optional, then the client still needs to include the parameter in the search parameters with its value set to null. Null picklist and text values can also be specified as a single blank.

When all parameter values have been collected and formatted into the POST body Json format, call the /search/execute/{amno} method to query the database and get the search results response.

Spatially restrict search execution

If the search definition specifies True for IsAoiLiRequired or IsAoiRequired, then the client must prepare and append an AOI object after the Parameters array in the Post body to the /search/execute/{amno} method. An array of AOI objects is returned from the {analyticalService}/Areas controller. The client could display the areas and let the user pick an area of interest to restrict his searches to. If the search definition has IsAoiliRequired=True then the selected AOI object must have a non-null AoiLi property value. Note that not all areas have a corresponding area of interest location identifier (AoiLi) value.

Any search that has IsAoiRequired set to true can also use an adhoc defined spatial filter instead of an area of interest. The client would create a GeoJson polygon and send it as the "SpatialFilter" parameter in the POST body of the search execute request. The execute search POST body can contain either an Aoi or SpatialFilter parameter - but not both. In both cases, the metadata defined values for AOI threshold limits and the ability to override the limits will be applied.

Use filter sets to restrict search execution

Any search execution can be further restricted by the specifying a FilterSet parameter in the POST body. A filter set specifies a previous trace or search result set to join against to restrict the feature instances that will be included in the response. The pending edits in a job can also serve as a filter set. The FilterSet property value must match one of the following types:

Trace.{traceId}

Search.{searchId}

Job.{jobId}

{table}.{column}.{value}

Measure features in a search result

Any search execution result set can be augmented with the measurement of the features. If the MeasureFeatures parameter in the POST body is set to true, then the three additional columns, LENGTH, AREA, and PERCENT, are added to the results. For linear geometry features, the LENGTH column contains the measured length in the units of the current configuration. Likewise, area geometry features contain the measured area. If the search result was spatially restricted by either an Aoi or an adhoc spatial filter, then the PERCENT column contains the ratio of the measure of the part of the feature geometry that is inside the spatial boundary divided by the measure of the total geometry. By default, all measurements are done using the curved Earth reference space, but the client can override that by setting the MeasureOnCurvedEarth parameter to false, which will measure using the projection reference space.

Fetch previous search results

Within the response to any successful search, the ResultId property value is the "handle" to the saved search results in the database. The search results will remain in the database until the client explicitly deletes them with a call to /search/results/delete.

When the search was executed, the client received either all or part of the results depending on whether paging control parameters were used on the search/execute request Url. At any point in the future, clients can pull additional pages of the results by calling /search/results/fetch?resultId={resultId}&pageSize={rowsPerPage}&pageNo={pageNumber}.

When pagination parameters are specified, the query results are returned in pages based on requested page number and page size. When no pagination parameters are specified, all of the search results are returned. To assist the clients in managing the paging of the results, the response header will contain the X-Paging-xxx set of header tags (i.e. X-Paging-PageNo, X-Paging-PageSize, X-Paging-PageCount, X-Paging-TotalRecordCount).

Augment the Search Results

Any search execution result set can be augmented with new attributes by providing the AUGMENT optional parameter. User can provide attribute numbers and attribute field name as input to the AUGMENT parameter. Call the /Search/Results/Fetch?resultId={resultId}&Augment={Attribute Number}&Augment={ComponentName.AttributeFieldName} to retrieve augmented parameters along with the search result set.

Aggregation on Search Results

Aggregation can be performed on the result set by providing aggregate optional parameters. Supported aggregates are SUM, MIN, MAX, AVG, GROUPBY, ORDERBY and DISTINCT. User can provide attribute numbers or response field names that needs to participate in the aggregate operation. Simple arithmetic operations can also be performed on the response fields for aggregation. Supported operators for arithmetic operation are +, -, *, /. The arithmetic expression will be evaluated for each response item and then the resulting aggregation will be performed. Call the /Search/Results/Fetch?resultId={resultId}&Sum={parameterName}&Min={parameterName}&Max={parameterName}&Avg={parameterName} to perform aggregation on the search result set.

Substitute on Search Results

Substitute operation can be performed on the result set parameters by providing the SUBST optional parameter. It is performed on individual attributes or attributes in specific ranges. All the operators supported by DataTable can be used in substitute operation. Call the /Search/Results/Fetch?resultId={resultId}&Subst={Substitute ParameterName},{Condition},{Substituted Value} to perform substitution functionality on the search result set.

Function Call on Search Results

An Oracle function which returns a scalar value can be executed by providing the FUNCTION optional parameter. The resultant value is added as a new parameter to the Search result set. Call the /Search/Results/Fetch?resultId={resultId}&Function={OracleFunctionName}@{ParameterName} to execute the oracle function and add to the search result set.

Display the search results on the map view

The ResultId property value is also used as part of the dynamic layer name for the search result. The name will be Search.{ResultId}. To display the results on the map view, the client first calls the WMS GetLayer method with LAYERS=Search.{ResultId} to get the GetCapabilities response that includes the bounding box to fit the map to in a subsequent call to the WMS GetMap method that also specifies the Layers=Search.{ResultId}. (See WMS Service methods for details).

Delete search results

Call the /search/results/delete?resultId={resultId from search/execute response} method to cleanup the saved search results in the database. It is the client's responsibility to do this cleanup since it is the only one that knows when it is finished working with a specific search result.

Supported application number for search workflows:

The bit mask value for NetWorks is 8. If the application parameter is not specified, then the default value of 8 is used for NetWorks Web Services. Execute the pl/sql statement if a search is intended to be displayed through NetWorks Analytical Service. UPDATE G3E_ATTRIBUTEQUERY SET G3E_APPLICATION = 8 WHERE G3E_AQNO=; Note: Perform Metadata Publish for the changes to be reflected.

Methods

Method Uri Description
GET /Details Gets the list of all details.
GET /Details/Fnos Get the list of FNOs that have details.
GET /Details/Fnos/{Fno} Get details by FNO.
GET /Details/Fnos/{Fno}/Names?name={name} Get details by FNO and name.
GET /Details/Names?name={name} Get details by name.
GET /search/searches Get search definitions.
GET /search/searches/categories Get the list of search categories.
GET /search/searches/{acno} Get search definitions by ACNO.
GET /search/quicksearches Get quicksearch definitions.
GET /Execute/{amno} Execute a search.
GET /Results/Delete Delete search results from the database.
GET /Search/Detail/{detailId} Gets the MBR of a detail given its detail number.
GET /Search/Detail/{detailId}/{fno} Gets the MBR of a detail given its detail number and feature number.
GET /Schematics Gets the list of all schematics.
GET /Schematics/Fnos Get the list of FNOs that have schematics.
GET /Schematics/Fnos/{Fno} Get schematics by FNO.
GET /Schematics/Fnos/{Fno}/Names?name={name} Get schematics by FNO and name.
GET /Schematics/Names?name={name} Get schematics by name.
GET /Settings Get the configured search settings.
GET /picklistvalues/{amno}/{ano} Returns the picklist values for the given search parameter.
GET /PickListValues/{ano} Returns the picklist values for the given attribute number.
POST /PickListValues/{ano} Returns the picklist values for the given attribute number based on the input filters.
GET /search/results/fetch Returns all the analysis (query or trace) results corresponding to the given result identifier.
