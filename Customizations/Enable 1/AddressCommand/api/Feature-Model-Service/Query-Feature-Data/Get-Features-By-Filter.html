Get Features By Filter

Returns the requested feature data for the specified feature type that matches the optional OData filter options and bounding box.

If the feature type in the route is followed by "/$count", then just the count of requested feature data that matches the OData filter option and bounding box is returned.

GET

Request URL Template

http://{hostname}/{service instance}/data/{featureName}[/$count]?[{oDataOptions}] [&BBOX={left,bottom,right,top}][&FilterSet={filterSetId}] [&MeasureFeatures={true|false}][&MeasureOnCurvedEarth={true|false}] [&Jobs={listOfJobNames} | ActiveJob={jobName}]

Request Parameters

Parameter Name Optional or Required Description
featureName Required Specifies the model feature type to retrieve data for.
oDataOptions Optional See the OData Options section below.
BBOX=left,bottom,right,top Optional Specifies a comma separated list of values (in the projection of the HxGN NetWorks Core configuration) that define a bounding box to use to spatially restrict the feature instances that will be included in the response.
MeasureFeatures= true or false Optional Specifies that the feature components that have linear or area geometry be measured. If the BBOX parameter is specified then the percent of the feature that falls within the bounding box is also computed. For linear geometry feature components, there will be Length and Percent attributes added to the component. For area geometry components, there will be Area and Percent attributes added to the component.
MeasureOnCurvedEarth= true or false Optional Specifies that the feature components that have linear or area geometry should be measured using the geographic reference space. If the parameter is false, then the measurement will use the projection reference space. If not specified, the measurement will be done using the geographic reference space.
FilterSet=filterSetId Optional Specifies a previous trace or search result set to join against to restrict the feature instances that will be included in the response. The pending edits in a job can also serve as a filter set. The filterSetId must match one of the following: (1) Trace.{traceId} (2) Search.{searchId} (3) Job.{jobId} (4) {table}.{column}.{value}
Jobs=listOfJobNames Optional Specifies a comma separated list of HxGN NetWorks Core jobs whose pending edits will participate in the query and response.
ActiveJob=jobName Optional Specifies the active HxGN NetWorks Core job whose pending edits will participate in the query and response.

OData Options

The OData parameters are used to query for specific instances of the feature type; and to select which information about the feature type to return; and to control how much feature information is returned in each response via the pagination parameters.

  • $filter={oDataExpression} - the filter parameter selects which feature instances to return. The oDataExpression can consist of the following items:

    • attribute - the value of the referenced attribute. For the simple attributes of the feature, just the attribute name is used (e.g. $filter=G3E_FID gt 15903 and G3E_FID lt 16000). For the attribute of a component or relationship, the qualified form {component/attribute} of the reference is used (e.g. $filter=SUBSTATION_RECORD/SUB_NUMBER eq 1145).

    • Logical operators -

      • and - returns true if both the left and right operands evaluate to true, otherwise it returns false. The null value is treated as unknown, so if one operand evaluates to null and the other operand to false, the and operator returns false. All other combinations with null return null.
      • or - returns false if both the left and right operands both evaluate to false, otherwise it returns true. The null value is treated as unknown, so if one operand evaluates to null and the other operand to true, the or operator returns true. All other combinations with null return null.
      • not - returns true if the operand returns false, otherwise it returns false. The null value is treated as unknown, so not null returns null.
      • eq - returns true if the left operand is equal to the right operand, otherwise it returns false. When applied to operands of entity types, the eq operator returns true if both operands represent the same entity, or both operands represent null. Each of the special values null, -INF, and INF is equal to itself, and only to itself. The special value NaN is not equal to anything, even to itself.
      • ne - returns true if the left operand is not equal to the right operand, otherwise it returns false. When applied to operands of entity types, the ne operator returns true if the two operands do not represent the same entity. Each of the special values null, -INF, and INF is equal to itself, and only to itself. The special value NaN is not equal to anything, even to itself.
      • gt - returns true if the left operand is greater than the right operand, otherwise it returns false. The special value INF is greater than any number, and any number is greater than -INF. The Boolean value true is greater than false. If any operand is null, the operator returns false.
      • lt - returns true if the left operand is less than the right operand, otherwise it returns false. The special value -INF is less than any number, and any number is less than INF. The Boolean value false is less than true. If any operand is null, the operator returns false.
      • ge - returns true if the left operand is greater than or equal to the right operand, otherwise it returns false. See rules for gt and eq for details.
      • le - returns true if the left operand is less than or equal to the right operand, otherwise it returns false. See rules for lt and eq for details.

    • Arithmetic operators - require operands that evaluate to numeric types. If an operand of an arithmetic operator is null, the result is null.

      • "-" - negation operator, represented by a minus (-) sign, changes the sign of its numeric operand.
      • add - adds the left and right numeric operands.
      • sub - subtracts the right numeric operand from the left numeric operand.
      • mul - multiplies the left and right numeric operands.
      • div - divide the left numeric operand by the right numeric operand.
      • mod - returns the remainder when the left numeric operand is divided by the right numeric operand. The sign of the result is the same as the sign of the left operand. If the right operand is zero, the request fails.
      • ( ) - The Grouping operator (open and close parenthesis) controls the evaluation order of an expression.

    • String built-in functions -

      • string concat( string, string ) - returns a string that appends the second parameter string value to the first.
      • boolean contains( string, string ) - returns true if the second string is a substring of the first string, otherwise it returns false. String comparison is case-sensitive, case-insensitive comparison can be achieved in combination with tolower or toupper.
      • boolean endswith( string, string ) - returns true if the first string ends with the second string, otherwise it returns false. String comparison is case-sensitive.
      • int32 indexof( string, string ) - returns the zero-based character position of the first occurrence of the second string in the first string, or -1 if the first string does not contain the second string. String comparison is case-sensitive.
      • int32 length( string ) - returns the number of characters in the string.
      • boolean startswith( string, string ) - returns true if the first string begins with the second string, otherwise it returns false. String comparison is case-sensitive.
      • string substring( string, int32 ) - returns the substring that begins with the Nth character (the integer second argument) and goes to the end of the string.
      • string substring( string, int32, int32 ) - returns a substring of the first parameter string value identified by selecting up to M characters starting at the Nth character (where N is the second parameter integer value and M is the third parameter integer value).
      • string tolower( string ) - returns the input parameter string value with all uppercase characters converted to lowercase according to Unicode rules.
      • string toupper( string ) - returns the input parameter string value with all lowercase characters converted to uppercase according to Unicode rules.
      • string trim( string ) - returns the input parameter string value with all leading and trailing whitespace characters, according to Unicode rules, removed.

    • Arithmetic built-in functions -

      • double ceiling( double ) - rounds the input numeric parameter up to the nearest numeric value with no decimal component.
      • double floor( double) - rounds the input numeric parameter down to the nearest numeric value with no decimal component.
      • double round( double ) -rounds the input numeric parameter to the nearest numeric value with no decimal component. The mid-point between two integers is rounded away from zero, i.e. 0.5 is rounded to 1 and ‑0.5 is rounded to -1.

    • Date / Time built-in functions - these function operate on three types: dateTimeOffset, date, and timeOfDay. A dateTimeOffset represents a date and time and time zone offset value. Literal operands are specified as YYYY "-" MM "-" DD "T" HH ":" mm [ ":" ss [ "." fractionalSeconds ] ] ( "Z" / SIGN HH ":" mm ) where HH is 24 hour value. The date type is specified as YYYY "-" MM "-" DD. The timeOfDay is specified as HH ":" mm [ ":" ss [ "." fractionalSeconds ] ].

      • date date( dateTimeOffset ) - returns the date part of the DateTimeOffset parameter value, evaluated in the time zone of the DateTimeOffset parameter value.
      • int32 day( date | dateTimeOffset ) - returns the day component Date or DateTimeOffset parameter value, evaluated in the time zone of the DateTimeOffset parameter value.
      • int32 hour( timeOfDay | dateTimeOffset ) - returns the hour component (0 to 23) of the DateTimeOffset or TimeOfDay parameter value, evaluated in the time zone of the DateTimeOffset parameter value.
      • int32 minute( timeOfDay | dateTimeOffset ) - returns the minute component (0 to 59) of the DateTimeOffset or TimeOfDay parameter value, evaluated in the time zone of the DateTimeOffset parameter value.
      • int32 month( date | dateTimeOffset ) - returns the month component of the Date or DateTimeOffset parameter value, evaluated in the time zone of the DateTimeOffset parameter value.
      • dateTimeOffset now( ) - returns the current point in time (date and time with time zone) as a DateTimeOffset value.
      • int32 second( timeOfDay | dateTimeOffset ) - returns the second component (0 to 59 for regular seconds, and 60 for leap seconds, without the fractional part) of the DateTimeOffset or TimeOfDay parameter value.
      • timeOfDay time( dateTimeOffset ) - rreturns the time part of the DateTimeOffset parameter value, evaluated in the time zone of the DateTimeOffset parameter value.
      • int32 year( date | dateTimeOffset ) - returns the year component of the Date or DateTimeOffset parameter value, evaluated in the time zone of the DateTimeOffset parameter value.

    • Collection built-in functions - the "any" and "all" lamda expressions are used to filter features based on instances of repeating components and relationships.

      • boolean {componentName}/any( var : var/{attribute} gt 0 ) - The any operator applies a Boolean expression to each instance of a repeating component or relationship and returns true if and only if the expression is true for any instance, otherwise it returns false. This implies that the any operator always returns false for an empty collection. The any operator can be used without an argument expression. This short form returns false if and only if the collection is empty. Example: $filter=Hyperlink_Record/any( q: contains(q/filePath, "schematic") will return true for any feature that has at least one Hyperlink_Record with a FilePath attribute that contains "schematic" as a substring.
      • boolean {componentName}/all( var : var/{attribute} gt 0 ) - The all operator applies a Boolean expression to each instance of a repeating component or relationship and returns true if and only if the expression is true for every instance, otherwise it returns false. This implies that the all operator always returns true for an empty collection.

  • $expand={featureComponentsRelationships} - a comma separated list of components and relationships of the feature instances to include in the response.

  • $select={attributes} - a comma separated list of the feature attributes to return in the response. Usually, the $select clause is nested in the componentList of the $expand option (e.g. "$expand=Substation_Record($select=Sub_Name,Sub_Type)" where Sub_Name and Sub_Type are attributes of the Substation_Record component).

  • $count=true - include a count of the feature instances in the response. The $count, $skip, $top and $orderBy parameters are used together to paginate the results when a large number of feature instances are expected in the response. For example, suppose the client wants to process the features in chunks of 1000 until all feature instances that match the filter criteria are processed. The first call the client makes includes $count=true&$top=1000&$orderBy={attribute}. If the odata.Count property in the response is less than 1000, the client knows that it has processed all of the results; otherwise, the client continues calling with $count=true&$skip={1000 * number of previous calls}&$top=1000&$orderBy={attribute} until the odata.Count value is less than 1000. Note that it is important to use an $orderBy attribute that will produce a deterministic order to the feature results.

  • $skip={numberToSkip} - specifies the number of feature instances from the query to skip over before forming the response.

  • $top={numberToReturn} - specifies the number of feature instances from the query to return in the response.

  • $orderBy={attributes} - specifies a comma separated list of component or relationship attributes used to order feature instances from the query before forming the response.

Sample Request

http://localhost/NetWorksFeatureModelService/data/SubStation?$expand=substation_record,substation_ar,hyperlink_record($select=G3E_CID,FILEPATH),common_record&$filter=Substation_Record/Sub_Number eq 1119&ActiveJob=16205

Sample Response

A JSON response is returned. The content is constrained by applying the $expand and $select parameters to the feature query results obtained after applying the $filter, BBOX, and / or FilterSet query parameters.

If a geographic component is included in the response, its G3E_GEOMETRY attribute will be formatted as GeoJson. Every geographic component will also include Longitude and Latitude properties. Only the first point in the component geometry is selected and converted to a geographic coordinate in decimal degrees. The primary use of this geographic longitude / latitude point is to allow OData clients (such as Excel and Power BI) that have simple map visualizers to display the feature’s location on a map. The Longitude and Latitude properties are directly bound to input fields of the map visualizers.
